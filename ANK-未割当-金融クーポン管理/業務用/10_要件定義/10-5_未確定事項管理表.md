# 10-5. 未確定事項管理表 (Issue Log)

**目的**: ヒアリングで判明した未確定事項を一元管理し、Owner / 期限 / Status で追跡する。  
**運用**: 週次レビュー (内部) で全件確認、月次顧客報告で残件サマリを共有。

---

## 1. 管理ルール

### 1.1 起票ルール
- ヒアリング / 会議で「未確定」が出たら **その場で ID 採番**
- 起票時必須項目: ID / 内容 / Owner / 期限 / 重要度 / 影響範囲

### 1.2 Status 定義
| Status | 意味 |
|---|---|
| Open | 未着手 / 確認中 |
| In Progress | 確認進行中 |
| Pending Decision | 決定待ち |
| Decided | 決定済 (本表からクローズ、Decision Log に転記) |
| Withdrawn | 取下げ |

### 1.3 重要度
| 重要度 | 意味 | 対応 SLA |
|---|---|---|
| 緊急 | 進行中フェーズが停止する | 1 週間以内決定 |
| 高 | 次フェーズ Exit を阻害 | 2 週間以内決定 |
| 中 | 影響あるが他項目で先行可 | 1 ヶ月以内決定 |
| 低 | 影響限定的 | 適時 |

### 1.4 影響範囲分類
- 業務要件 (機能) / 非機能 / 規制対応 / アーキ / 連携 / 体制 / 商務

## 3. 未確定事項のサマリ (運用)

### 3.1 月次集計テンプレ

```markdown
## 未確定事項サマリ YYYY-MM

### 全件
- 累計起票: NN 件
- 現在 Open: NN 件
- 緊急 / 高: NN 件
- 中 / 低: NN 件
- 期限超過: NN 件

### 重要度別 Open 件数
- 緊急: N (うち期限超過 M)
- 高: N (うち期限超過 M)
- 中: N
- 低: N

### 今月クローズ
- N 件 (Decided / Withdrawn 別)

### 期限超過リスト (要対応)
- (該当 ID 一覧)
```

### 3.2 顧客報告用サマリ (月次顧客報告会)

- 全体傾向 (増減)
- 緊急 / 高の状況
- 期限超過した項目と理由
- 顧客側に意思決定が必要な項目 (依頼)

## 4. Decision Log への転記ルール

Status が「Decided」に変わった項目は **Decision Log** (別ファイル) に転記:

```markdown
# Decision Log

## DEC-001 (旧 ISS-001) PF 側 PoC ガイドラインスケジュール
- 決定日: 2026-08-XX
- 決定者: 顧客責任者 + PF 側責任者 + PM
- 内容: ガイドライン v1.0 を 2026-09-末に提供。v2.0 を 2026-11-末。
- 根拠: 2026-08-XX 会議議事録
- 影響: マスタープラン 2026/9, 2026/12 マイルストーンに反映
```

Decision Log は永続保管 (Confluence / S3 / リポジトリ)。要件定義以降も追加し続ける。

---

## 5. レビュータイミング

| タイミング | 内容 | 参加者 |
|---|---|---|
| 日次 (PM 朝のルーチン) | 自分の Owner 案件の進捗確認 | PM (自分) |
| 週次 (月曜キックオフ) | 全件状況確認 | PM + チーム |
| 週次 (金曜 顧客報告会) | 残件サマリ共有 | PM + 顧客 + 元請 PL |
| 月次 | 期限超過レビュー + 顧客レビュー | PM + 顧客 |
| フェーズ Exit 前 | 該当フェーズに関連する項目をすべて Decided へ | PM + チーム |
