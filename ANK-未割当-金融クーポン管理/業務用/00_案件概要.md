## 1. 案件背景

### 1.1 ビジネス背景

| 項目 | 内容 |
|---|---|
| 推進母体 | 大手金融機関 (グループ持株会社配下) |
| 戦略テーマ | グループ顧客化促進・グループ外損失利益低減 |
| 本システムの役割 | グループ顧客に提供する **特別金利電子クーポン** の発行・利用・失効を一元管理する |
| 親システム | 顧客名寄せ親システム (全店名寄せ相当) — 本システムから見ると顧客ID/属性のマスタソース |
| 関連施策 | (要記入: 中期経営計画上の位置付け、対象顧客セグメント、KPI) |

### 1.2 技術背景 (重要)

| 項目 | 内容 |
|---|---|
| 旧計画 | 親システムの共通基盤 (コンテナ環境) を流用して構築予定 |
| 計画変更トリガ | 既存仮想化基盤ベンダー (旧来 PF) の戦略変更により次期基盤を AWS ベースの「次期クラウド共通基盤 (オープン勘定系 PF 相当)」に移行 |
| 本システムへの影響 | クラウドシフト対象に追加。PF 側は **現在 PoC 中**、PF 側からガイドラインなどが提供される予定 |
| 設計時の前提 | PF 側ガイドラインが要件定義期間 (2026/4-12) 中に複数イベントで提供される。**確定情報は限定的に取得していく前提** |

### 1.3 担当範囲

本案件は **PM 兼 SA (構築フェーズ一気通貫担当)** として、以下を担当する:

- 要件定義 → 基本設計 → 詳細設計 → 構築 (MUT/LT/ST/開発結合) → 運用機能開発 → 結合試験 → 本番構築・結合 → 総合テスト
- PF 側との連携・調整 (ガイドライン受領・差分整理・PF 側依頼)
- 親システム (名寄せ) 側との I/F 調整
- 顧客側部門 (販促企画 / IT 統括) との要件すり合わせ
- ベンダー / BP 要員管理 (最大 4 名体制)

> **担当外 (Out of Scope) 想定**: PF 共通基盤本体の設計・構築 (PF 側別案件) / 親システムの改修 / カットオーバー後の長期運用保守 (別契約となる可能性)

## 3. システム概要 (要件定義 Day-1 仮説)

> **重要**: 以下は要件定義開始前の **PM 仮説**。Day-1 ヒアリングで全項目確認・更新する。

### 3.1 想定 AWS サービス (要件定義時点の想定)

| 領域 | サービス | 用途 |
|---|---|---|
| ネットワーク | VPC, Subnet, NAT GW, Route53, TGW(PF 側経由) | システム境界 / 名前解決 / 経路 |
| コンピュート | ECS (Fargate 想定) | アプリ実行基盤 (API / バッチ / Worker) |
| データベース | Aurora PostgreSQL | クーポン情報、利用履歴、設定マスタ |
| ストレージ | S3 (各種), EFS (共有ファイル) | ログ・帳票・ファイル受け渡し |
| 認証認可 | IAM, IAM Identity Center (PF 側連携想定) | 利用者・サービス権限 |
| メッセージング | (未定) SQS / EventBridge / SNS | 親システム連携、内部疎結合 |
| 監視運用 | CloudWatch (Logs / Metrics / Alarm), Change Calendar | 稼働監視 / 変更管理凍結期間 |
| セキュリティ | KMS, Secrets Manager, GuardDuty (PF 集中)、SecurityHub (PF 集中) | 暗号化 / 機密管理 / 脅威検知 |
| デプロイ | CodePipeline / CodeBuild または GitLab CI / Jenkins (CI/CD ガイドライン未確定) | 構築〜本番デプロイ |

> 要求スキル一覧に明記された想定: EC2, VPC, IAM, S3, AuroraDB, EFS, ECS, Route53, Change Calendar, CloudWatch ([案件概要原文])  
> **PoC 中の PF 側方針で変更の可能性あり** (例: ECS → EKS、CodePipeline → Jenkins 等)

### 3.2 想定アプリケーション機能 (仮説)

- クーポン発行管理 (キャンペーン定義、対象顧客抽出 (親システム連携)、発行)
- クーポン利用受付 (顧客提示 → 利用判定 → 金利優遇情報を勘定系へ渡す I/F)
- クーポン履歴管理 (発行・利用・失効ステータス管理、監査ログ保管)
- 帳票・分析 (利用状況レポート、分析データ抽出)
- マスタ管理 (キャンペーンマスタ、商品マスタ、利用条件マスタ)
- 運用機能 (バッチ、夜間処理、データクレンジング、システム監視、リカバリ)

### 3.3 連携先 (Day-1 確認)
- 親システム (顧客名寄せ親システム): 顧客ID / 属性取得
- 勘定系 (PF 側経由) : 金利優遇情報の連携
- データ分析基盤: クーポン利用実績連携
- 認証基盤 (IAM IdC / SSO): 利用者ログイン
- 外部 (顧客向けチャネル: 銀行アプリ / Web): クーポン提示・利用
