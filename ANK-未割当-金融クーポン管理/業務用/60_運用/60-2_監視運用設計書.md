## 1. 監視全体像

```
[アプリ] → [FireLens] → [CloudWatch Logs] → [Logs Insights (短期)]
                                          ↘ [Splunk] (長期、要件次第)
[アプリ] → [CloudWatch Metrics + X-Ray]
[AWS] → [CloudWatch Metrics] (リソース)
                          ↓
                  [CloudWatch Alarm + Composite Alarm]
                          ↓
                  [SNS Topic] → [Slack + PagerDuty + ServiceNow]
                                                   ↓
                                              [Tier 1 一次対応]
                                                   ↓
                                              [Runbook 実行 or エスカレ]

[GuardDuty / SecurityHub / Config] → [SecurityHub Findings] → [SNS] → [監査部門]
[Cost Anomaly Detection] → [SNS] → [Slack #cost]
```

## 6. Composite Alarm (合成アラーム)

### 6.1 用途
- 複数 Alarm の AND/OR 評価で誤検知低減
- 例: 「API 5xx 増加 AND ECS Task 失敗」 → 本物の障害

### 6.2 例

```hcl
resource "aws_cloudwatch_composite_alarm" "api_real_outage" {
  alarm_name = "coupon-prod-api-real-outage"
  alarm_rule = "ALARM(coupon-prod-alb-5xx) AND ALARM(coupon-prod-ecs-task-failures)"
  
  alarm_actions = [aws_sns_topic.alert_p1.arn]
}
```

出典: https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Create_Composite_Alarm_With_AWS_Console.html

## 8. 監視運用ルール

### 8.1 当番制
- Hyper Care 期間 (Cutover 後 90 日) は案件チーム当番
- 平日: 営業時間中監視 + オンコール (16-翌 9 時)
- 休日: オンコール

### 8.2 アラート対応フロー
1. 通知受信
2. Slack で「対応中」宣言
3. Runbook 確認 (Confluence)
4. 一次対応 (15 分以内 for P1)
5. エスカレーション (必要時)
6. 復旧確認
7. Postmortem (P1 / 重要 P2)

### 8.3 アラート抑制
- 既知の問題 (修正中) は AWS Chatbot 抑制ルール
- メンテナンス時間帯は Change Calendar 連動

### 8.4 アラートチューニング
- 月次で誤検知 / 見逃し分析
- 閾値調整 (CAB 経由)
- 不要 Alarm 廃止 (棚卸)

## 9. 障害復旧 (Auto Recovery)

### 9.1 自動復旧パターン

| パターン | トリガー | アクション |
|---|---|---|
| ECS Task 異常終了 | TaskStopReason 異常 | Service が自動再起動 (Desired Count 維持) |
| Aurora Failover | AZ 障害 | Aurora 自動 Failover (60-120 秒) |
| ALB Target Unhealthy | Health Check 失敗 | ALB が自動振り分け除外 |
| Lambda Memory 不足 | OOM | Memory 増設 (要 IaC 変更) |

### 9.2 半自動復旧
- アラート受信 → Slack に「自動対応開始」通知 → Lambda で対応 → 結果通知

### 9.3 手動復旧
- Runbook 確認 → 手順実行 → 結果記録 → Postmortem
