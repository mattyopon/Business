# 商談時ヒアリングシート

**目的**: 商談時に短時間 (60 分) で確認したい項目のサマリ。詳細は要件定義中の [10-4_ヒアリングシート](../業務用/10_要件定義/10-4_ヒアリングシート.md) を使う。

---

## 1. 案件全体 (10 分)

- [ ] 案件主管部門・責任者
- [ ] プロジェクト全体予算 / 月次想定費用
- [ ] カットオーバー希望日
- [ ] 体制 (PM / SA / IaC / QA / 運用) の構成・人数
- [ ] 既存運用部門 (Cutover 後引き継ぎ先) の位置付け

## 2. 技術前提 (15 分)

- [ ] AWS リージョン (Tokyo / Osaka 利用方針)
- [ ] DR サイト (大阪) 採用可否
- [ ] コンテナ基盤の希望 (ECS / EKS)
- [ ] DB エンジン (Aurora PostgreSQL / MySQL / その他)
- [ ] CI/CD ツール (GitLab / Jenkins / CodePipeline)
- [ ] IaC は Terraform で良いか
- [ ] 認証基盤 (IAM Identity Center) の集中管理状況
- [ ] 監視・ログ基盤 (Splunk / Datadog / CloudWatch)

## 3. PF 側状況 (15 分)

- [ ] PoC のスコープ・スケジュール
- [ ] ガイドライン受領タイミング
- [ ] PF 側責任者・主担当
- [ ] 利用可能 AWS サービスの制約
- [ ] アカウント発行プロセス
- [ ] NW 接続方式 (TGW / VPC Peering)
- [ ] KMS / Identity Center / 監視・セキュリティサービスの管理範囲

## 4. 親システム (顧客名寄せ) 状況 (10 分)

- [ ] 親システム責任者・主担当
- [ ] 親システムの稼働環境 (オンプレ / クラウド)
- [ ] I/F 方式 (バッチ / API)
- [ ] 顧客 ID 形式
- [ ] I/F 仕様確定見込み
- [ ] テスト環境利用可否

## 5. 規制対応 (10 分)

- [ ] FISC 第 11 版対応の現状 (他システム実績)
- [ ] AWS FISC リファレンス第 2 版利用方針
- [ ] 監査部門責任者
- [ ] 個人情報保護方針 (顧客 ID のみ保持で OK か)
- [ ] PCI DSS 適用判定 (カード情報を扱うか)
- [ ] 監査ログ保管期間 (7 年想定)

---

## 6. 質問の優先度

### 商談で必ず確認 (Must)
1. 案件主管部門・責任者
2. PF 側 PoC スケジュール
3. 親システム I/F 確定見込み
4. 体制・予算
5. カットオーバー希望日
6. IaC / CI/CD 方針
7. FISC 対応の現状

### 商談後の追加ヒアリング可 (Should)
1. 個別サービスの選定理由
2. 既存 SOC との連携詳細
3. 監視・ログの詳細
4. 個別パラメータ

### 要件定義中に詳細化 (Could)
1. パラメータレベル
2. 個別シナリオ
3. 詳細スケジュール

---

## 7. ヒアリング後のアクション

- [ ] 議事録作成 (当日中)
- [ ] 元請 PL に共有
- [ ] 提案資料更新
- [ ] 想定 Q&A 更新
- [ ] リスクレジスタ初期化
- [ ] 未確定事項管理表初期化
