## 2. 案件理解

### 2.1 ビジネス背景の理解
- グループ顧客化促進 + グループ外損失利益低減
- 特別金利電子クーポンの管理子システム
- 親システム「顧客名寄せ親システム」の子プロジェクト

### 2.2 技術環境変化の理解
- もともと親システムの共通基盤 (コンテナ環境) で構築予定
- 既存仮想化基盤ベンダーの戦略変更により、次期クラウド共通基盤 (AWS) へ移行
- PF 側は PoC 中、ガイドラインが順次提供される前提

### 2.3 主要技術要素
- AWS: EC2 / VPC / IAM / S3 / Aurora / EFS / ECS / Route 53 / Change Calendar / CloudWatch
- IaC: Terraform 想定
- CI/CD: PF 側ガイドライン依存 (GitLab / Jenkins / CodePipeline 等)
- 規制対応: FISC 第 11 版 / 金融庁ガイドライン

## 3. 提案アプローチ

### 3.1 PM としての価値提供
1. **PF 側待ち / 先行可能タスクの仕分け** → 案件停止リスクを構造で防ぐ
2. **未確定事項管理表** で全領域の未確定を可視化 + 顧客への意思決定依頼を構造化
3. **FISC 第 11 版マッピング** を要件定義中に着手 → 基本設計以降の手戻り防止
4. **AWS FISC リファレンス第 2 版** をベースに監査部門と早期合意
5. **Change Calendar 連動の CI/CD** で凍結期間管理の自動化

### 3.2 体制提案
- 要件定義: PM + SA 1 名想定
- 基本/詳細設計: PM + SA 2 名 + IaC 1 名
- 構築 + UT: PM + IaC 1-2 名 + QA 1 名
- 結合 + 総合: PM + QA 1 名 + 運用 1 名 + IaC 1 名
- ピーク時 4 名 (顧客要望に合致)

### 3.3 リスク対応
