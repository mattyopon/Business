# 04. 監視設計書

## 1. 目的

検索システムのインフラ / アプリケーション層を CloudWatch + OpenSearch ダッシュボードを軸に観測し、SLO 違反前にアラートで気付ける状態を作る。

## 2. SLO / SLI

| サービス | SLI | SLO (月次) |
|---------|-----|-----------|
| API Gateway | 5xx率 | ≤ 0.1% |
| API Gateway | p95 latency | ≤ 800ms |
| OpenSearch | クラスタヘルス green 維持時間 | ≥ 99.5% |
| OpenSearch | 検索 p95 latency | ≤ 500ms |
| Cognito | サインイン成功率 | ≥ 99% |

エラーバジェット枯渇時はリリース凍結 (停止可否は障害対応リーダーが判断)。

## 3. メトリクス

### 3.1 OpenSearch

| メトリクス | 用途 | 閾値 |
|----------|------|------|
| `ClusterStatus.yellow` | 部分劣化検知 | > 0 が 5分続いたら Warning |
| `ClusterStatus.red` | 重大障害 | > 0 が 1分続いたら Critical |
| `CPUUtilization` | データノードCPU | > 80% / 10min Warning |
| `JVMMemoryPressure` | GC圧迫 | > 75% / 10min Warning, > 90% / 5min Critical |
| `FreeStorageSpace` | EBS残量 | < 25% Warning, < 10% Critical |
| `SearchLatency` p95 | 検索遅延 | > 500ms / 10min Warning |
| `IndexingLatency` p95 | 投入遅延 | > 1000ms / 10min Warning |
| `MasterReachableFromNode` | マスター不達 | < 1 で Critical |
| `KMSKeyError` | 暗号化キー異常 | > 0 で Critical |

### 3.2 API Gateway

| メトリクス | 閾値 |
|----------|------|
| `5XXError` | 1% / 5min Warning, 5% / 5min Critical |
| `4XXError` | 急増 (前週比 +3σ) で Warning |
| `Latency` p95 | > 800ms / 10min Warning |
| `IntegrationLatency` p95 | > 600ms / 10min Warning |
| `Count` (異常低下) | 平常時比 -50% / 10min Warning |

### 3.3 Lambda

| メトリクス | 閾値 |
|----------|------|
| `Errors` | > 1% / 5min Warning |
| `Throttles` | > 0 / 5min Warning |
| `Duration` p95 | > 関数 timeout の 50% で Warning |
| `IteratorAge` (ストリーム) | > 60s Warning |

### 3.4 Cognito

| メトリクス | 閾値 |
|----------|------|
| `SignInSuccesses` 急減 | -50% / 10min Warning |
| `TokenRefreshThrottles` | > 0 で Warning |

## 4. ログ

| ソース | 保管先 | 保管期間 |
|-------|--------|---------|
| API Gateway Access Logs | CloudWatch Logs | 90日 → S3 アーカイブ (1年) |
| API Gateway Execution Logs | CloudWatch Logs | 30日 |
| Lambda | CloudWatch Logs | 90日 |
| OpenSearch Slow Logs (Search/Indexing) | CloudWatch Logs | 30日 |
| OpenSearch Application Logs | CloudWatch Logs | 90日 |
| Cognito | CloudWatch + CloudTrail | 90日 (Trail は 1年) |
| VPC Flow Logs | S3 | 90日 |

ログクエリは CloudWatch Logs Insights を主とし、OpenSearch Dashboards への取り込みはトラフィック増加時に検討。

## 5. ダッシュボード

| ダッシュボード | 用途 | 想定閲覧者 |
|--------------|------|-----------|
| `search-overview` | クラスタ健康度 / レイテンシ / トラフィックの俯瞰 | SRE / 開発 |
| `search-error-drilldown` | 5xx / Lambda Errors のドリルダウン | SRE / 開発 |
| `cost-watch` | OpenSearch / NAT GW のコスト推移 | 案件責任者 |

## 6. アラート通知

| 重要度 | 通知先 | 応答 SLA |
|--------|--------|---------|
| Critical | PagerDuty → SRE 当番 + Slack `#search-alert` | 15分以内に一次対応着手 |
| Warning | Slack `#search-alert` | 翌営業日までに対応方針決定 |
| Info | Slack `#search-info` (静かに記録) | - |

CloudWatch Alarms → SNS → AWS Chatbot / PagerDuty で配送。

## 7. 死活監視 (外形)

- Route 53 Health Check で `/_healthcheck` を 1分間隔監視 (3拠点)
- 連続2回失敗で Critical アラート (回線断と区別するため複数拠点判定)
