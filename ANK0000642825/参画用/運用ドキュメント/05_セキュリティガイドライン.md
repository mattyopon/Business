# 05. セキュリティガイドライン

## 1. 適用範囲

本ガイドラインは検索システム (OpenSearch / API Gateway / Cognito / Lambda / VPC) と運用作業全体を対象とする。

## 2. 認証 / 認可

### 2.1 エンドユーザー

- Cognito User Pool (MFA OPTIONAL、管理者ロールは REQUIRED)
- JWT (ID Token / Access Token) は短命 (1h)。Refresh Token は HttpOnly Cookie / Secure Storage で保管
- ログアウト操作で Refresh Token を Revoke、Access Token はクライアント側で破棄

### 2.2 運用者

- AWS Account へのアクセスは IAM Identity Center (旧 SSO) 経由。長期 IAM User の発行禁止
- 本番リソースは PermissionSet `SearchOpsAdmin` を 1日以内の権限委譲セッションで利用
- 全運用者に MFA 強制

### 2.3 システム間

- Lambda → OpenSearch: IAM Role + 署名リクエスト (SigV4)。OpenSearch 側で `internal_user_database_enabled=false`、`master_user` は IAM Role
- CI/CD → AWS: GitHub OIDC + IAM Role (Workload Identity 連携)。**長期 Access Key の GitHub Secrets 保存は禁止**
- Terraform: state は S3 + DynamoDB lock。state はサーバーサイド暗号化 (KMS) 必須

## 3. ネットワーク

- VPC: パブリック / プライベートサブネット分離。OpenSearch / Lambda はプライベートのみ
- セキュリティグループは最小権限 (Lambda SG から OpenSearch SG への 443 のみ)
- VPC Endpoint: S3, KMS, CloudWatch Logs を Interface / Gateway で配置
- WAF Web ACL: AWS Managed Rules `CommonRuleSet`, `KnownBadInputs`, `BotControl`, Rate-based 2000 req/5min

## 4. データ保護

### 4.1 暗号化

- 保存時: OpenSearch / EBS / S3 / CloudWatch Logs / KMS CMK (`aws/<service>` ではなくカスタマー管理キー)
- 転送時: TLS 1.2 以上 enforce。OpenSearch `domain_endpoint_options.tls_security_policy = "Policy-Min-TLS-1-2-2019-07"`

### 4.2 機密データの取扱

- PII (氏名、メールアドレス、電話番号) を OpenSearch にインデックスする場合は、最小フィールド + マスキング (`@example.com` 等) + アクセス監査
- ログには PII を出力しない。Cognito の `email`, `sub` は構造化ログでマスキング推奨
- 機密ドキュメントは別インデックスに分離し、index-level の ACL (FGAC) を適用

## 5. アクセス制御 (Fine-Grained Access Control)

OpenSearch FGAC を有効化:

- `all_access` ロールは IAM Role 経由でのみ利用、人による直接付与は禁止
- 検索アプリ用ロール: `indices:data/read/*` のみ
- 管理アプリ用ロール: `indices:data/write/*`, `indices:admin/*` (作成 / mapping 更新)

## 6. ログ / 監査

- CloudTrail: 全リージョン有効、Management Events + Data Events (S3, Lambda) を S3 + CloudWatch へ
- VPC Flow Logs: REJECT のみ S3。ALL は cost 都合で対象システムのみ
- AWS Config: 主要リソース (OpenSearch / KMS / IAM / VPC) を recorder 対象
- GuardDuty + Security Hub を有効化。Findings は Slack + メールに集約

## 7. シークレット管理

- AWS Secrets Manager または Parameter Store (SecureString) を利用。リポジトリへの平文格納禁止
- アプリケーションは IAM Role でシークレット参照、KMS で復号
- ローテーション: 90日ごと (重大事故時は即時)

## 8. 脆弱性管理

- Lambda ランタイム: 公式サポート切れバージョン使用禁止 (例: Node.js / Python の EOL バージョン)
- コンテナイメージは ECR Image Scan + Trivy / Snyk で CI 段階スキャン
- 月次で Critical / High の脆弱性をトリアージし 30日以内に対応
