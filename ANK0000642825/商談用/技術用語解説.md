# 技術用語解説 - 検索システムインフラ構築支援案件

本案件で使用される可能性のある技術用語を解説します。

---

## 1. AWS基盤サービス

### Amazon EC2 (Elastic Compute Cloud)
仮想サーバーを提供するサービス。検索エンジンやアプリケーションサーバーのホスティングに使用。

### Amazon VPC (Virtual Private Cloud)
AWS内に論理的に分離されたプライベートネットワークを構築するサービス。セキュリティグループやNACLでトラフィック制御。

### AWS IAM (Identity and Access Management)
AWSリソースへのアクセスを安全に管理するサービス。最小権限の原則に基づいてポリシーを設計。

---

## 2. 検索関連サービス

### Amazon OpenSearch Service
フルマネージドの検索・分析エンジン。Elasticsearchをベースとしており、全文検索、ログ分析、リアルタイム監視に使用。

**主な機能**:
- 全文検索
- ファセット検索（絞り込み）
- リアルタイムインデクシング
- OpenSearch Dashboards (旧称: Kibana。Elasticsearch から fork した OpenSearch では `OpenSearch Dashboards` が正式名称)

### Amazon CloudSearch
フルマネージドの検索サービス。シンプルな検索要件に適している。設定が容易で運用負荷が低い。

### Elasticsearch
オープンソースの分散型検索・分析エンジン。大量のデータに対するリアルタイム検索が可能。

---

## 3. 認証・API管理

### Amazon Cognito
ユーザー認証・認可を提供するサービス。

**コンポーネント**:
- **User Pool**: ユーザーディレクトリ、サインアップ/サインイン機能
- **Identity Pool**: 一時的なAWS認証情報を発行

### Amazon API Gateway
REST API、HTTP API、WebSocket APIを作成・管理するサービス。

**主な機能**:
- リクエストのルーティング
- 認証・認可
- スロットリング（流量制御）
- キャッシュ

### OAuth 2.0 / OpenID Connect (OIDC)
認証・認可の標準プロトコル。Cognitoはこれらをサポート。

---

## 4. コンテナ関連

### Amazon ECS (Elastic Container Service)
コンテナオーケストレーションサービス。DockerコンテナをAWS上で実行・管理。

**起動タイプ**:
- **Fargate**: サーバーレス（インフラ管理不要）
- **EC2**: EC2インスタンス上でコンテナ実行

### Amazon EKS (Elastic Kubernetes Service)
マネージドKubernetesサービス。大規模なコンテナ運用に適している。

### Amazon ECR (Elastic Container Registry)
Dockerコンテナイメージを保存・管理するレジストリサービス。

---

## 5. ネットワーク

### Application Load Balancer (ALB)
L7（HTTP/HTTPS）レベルでの負荷分散。パスベースルーティング、ホストベースルーティングが可能。

### Network Load Balancer (NLB)
L4（TCP/UDP）レベルでの負荷分散。超低レイテンシが必要な場合に使用。

### Amazon CloudFront
グローバルCDN（Content Delivery Network）。静的コンテンツ配信の高速化、DDoS対策。

### AWS PrivateLink
VPC間やAWSサービスへのプライベート接続を提供。インターネットを経由せずに通信。

---

## 6. ストレージ

### Amazon S3 (Simple Storage Service)
オブジェクトストレージ。検索インデックスのバックアップ、ログ保存、静的コンテンツ配信に使用。

**ストレージクラス**:
- Standard: 頻繁にアクセスするデータ
- Intelligent-Tiering: アクセスパターンが不明なデータ
- Glacier: アーカイブ用（低コスト）

### Amazon EBS (Elastic Block Store)
EC2インスタンス用のブロックストレージ。データベースやファイルシステムに使用。

**ボリュームタイプ**:
- gp3: 汎用SSD（コスト効率重視）
- io2: プロビジョンドIOPS（高性能）

### Amazon EFS (Elastic File System)
マネージドNFSファイルシステム。複数のEC2インスタンスから同時アクセス可能。

---

## 7. データベース

### Amazon RDS (Relational Database Service)
マネージドリレーショナルデータベース。MySQL、PostgreSQL、Oracle等をサポート。

### Amazon Aurora
AWS独自の高性能リレーショナルデータベース。MySQL/PostgreSQL互換で、標準の5倍高速。

### Amazon ElastiCache
インメモリキャッシュサービス。Redis/Memcachedをサポート。検索結果のキャッシュに使用可能。

### Amazon DynamoDB
フルマネージドNoSQLデータベース。高速なキーバリューアクセスに適している。

---

## 8. 監視・ログ

### Amazon CloudWatch
AWS リソースとアプリケーションの監視サービス。

**機能**:
- メトリクス収集
- ログ管理（CloudWatch Logs）
- アラーム設定
- ダッシュボード

### AWS CloudTrail
AWSアカウント内のAPIコールを記録。セキュリティ監査、コンプライアンス対応に必須。

### AWS X-Ray
分散トレーシングサービス。マイクロサービス間のリクエストフローを可視化。

---

## 9. セキュリティ

### AWS WAF (Web Application Firewall)
Webアプリケーションを一般的な攻撃から保護。SQLインジェクション、XSSなどを防御。

### AWS Shield
DDoS攻撃からの保護サービス。Standard（無料）とAdvanced（有料）がある。

### AWS KMS (Key Management Service)
暗号化キーの作成・管理サービス。保存データの暗号化に使用。

### AWS Secrets Manager
シークレット（DB認証情報、APIキー等）を安全に管理。自動ローテーション機能。

---

## 10. IaC (Infrastructure as Code)

### Terraform
HashiCorp社のIaCツール。HCL（HashiCorp Configuration Language）でインフラを定義。

### AWS CloudFormation
AWS純正のIaCサービス。YAML/JSONでインフラをテンプレート化。

### AWS CDK (Cloud Development Kit)
プログラミング言語（TypeScript、Python等）でインフラを定義するフレームワーク。

---

## 11. 検索システムアーキテクチャ用語

### インデックス
検索対象データを高速に検索できるよう構造化したもの。

### シャード
大量のデータを分割して保存する単位。検索の並列処理を可能にする。

### レプリカ
シャードの複製。可用性向上と読み取りスループット向上に寄与。

### マッピング
ドキュメントの構造定義。フィールドのデータ型やアナライザーを指定。

### アナライザー
テキストをトークン（単語）に分割する処理。日本語対応には形態素解析が必要。

### 転置インデックス
単語からドキュメントへの逆引きインデックス。全文検索の基本データ構造。
