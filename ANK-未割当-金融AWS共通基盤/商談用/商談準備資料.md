# 金融機関 AWS クラウド共通基盤案件 スキルシート

## 1. 概要

### プロフィール
- **経験年数**: 約5年（インフラ構築・運用）
- **得意領域**: AWS、コンテナ技術、SRE/監視運用
- **資格 (取得歴)**: AWS Certified Solutions Architect / Developer / SysOps Administrator – Associate を 2020 年に取得。AWS 認定の有効期限は取得から 3 年で再認定が必要なため、2026 年 5 月時点の現役有効性は商談時に最新状況を共有 (再認定済の場合は更新年も提示)

## 2. 経歴

### 【経験①】大手広告代理店 電車内広告配信システム（2023年8月〜2025年1月）

#### 概要
電車内広告動画配信システムのインフラ構築・運用を担当。

#### 技術スタック
- **AWS**: CloudFront, WAF, ALB, EC2, ECS, Aurora MySQL
- **コンテナ**: Docker, ECS + EC2
- **CI/CD**: GitHub Actions
- **動画処理**: Lambda + ffmpeg（4沿線対応）
- **セキュリティ**: GuardDuty, AWS Config, CloudTrail, Inspector

#### 担当業務
- CloudFront + WAF、ALB + EC2×2台によるWordPress冗長構成の設計・構築
- ECS + EC2（Docker コンテナ）基盤の構築
- Lambda + ffmpegによる動画変換パイプラインの実装
- GitHub Actionsを使用したCI/CDパイプラインの構築
- プライベートサブネット + SSM経由SSH設計
- クライアントセキュリティ基準対応、AWS Inspector脆弱性対応

#### 成果
- **コンテナ技術**: ECS + Dockerによるコンテナ基盤の設計・構築
- **CI/CD構築**: GitHub Actionsを使用した自動デプロイパイプライン構築
- **セキュリティ**: 企業セキュリティ基準に準拠したインフラ設計
- **動画処理**: サーバーレス（Lambda）を活用した動画変換パイプライン

### 【経験②】大手放送局グループ MSP監視運用（2024年1月〜2025年6月）

#### 概要
大手放送局グループの複数サービスに対する24/365監視運用代行を担当。

- 障害一次対応フロー設計・エスカレーションルール策定
- 24/365監視運用

#### 監視対象
ECS Fargate, Fastly CDN, RDS, ElastiCache等

#### 成果
- **SRE実践**: 24/365監視運用、Runbook整備、インシデント対応フロー設計
- **監視基盤**: New Relic APM/Infrastructureを使用した監視設計
- **コンテナ運用**: ECS Fargateの運用経験

## 5. 本案件における経験との適合性

本案件は金融機関における大規模クラウドリフトのための共通基盤要件定義および基本設計を主たる対象としている。本案件と**直接同等の「マルチアカウント / Landing Zone / 金融共通基盤」プロジェクト経験は無い**前提で、以下の隣接領域の実績を活用する形でのコミットを想定する。

| 本案件で求められる経験 | 私の実績 (隣接領域) | 本案件でのコミット範囲 |
|---|---|---|
| マルチアカウント / Organizations / Control Tower / LZA 設計 | 単一アカウントベースの AWS 設計を 5年。Organizations / Control Tower / LZA の本番導入経験は無し | AWS 公式ガイド / LZA reference architecture を一次資料として、設計レビューと意思決定の整理に参画。導入の主担当は別途経験者と並走 |
| セキュリティサービス (GuardDuty / Inspector / Config / CloudTrail / WAF 等) | 広告配信案件で GuardDuty / Inspector / Config / CloudTrail / AWS WAF の運用とクライアントセキュリティ基準対応を実施 | 同等の運用知見を共通基盤の検知 / 通知 / 自動化設計にそのまま転用 |
| CI/CD (GitHub Actions) の構築 | 広告配信案件で GitHub Actions による自動デプロイパイプラインを実装 | 承認ゲート運用および IaC 静的解析 (Checkov / tfsec) を含むパイプライン設計に対応 |
| 24/365 監視および Runbook 整備 | 放送局 MSP 案件で New Relic / Zabbix / CloudWatch による 24/365 監視と Runbook / エスカレーション設計の実績あり | 共通基盤利用者向けの運用ガイドライン整備に直接転用可能 |
| 要件定義 → 詳細設計 → 構築 → 運用の一気通貫 | 広告配信案件 (設計〜構築〜運用) と MSP 案件 (運用設計〜実運用) | フェーズ横断の意思決定整理に貢献 |

### 補強が望ましい領域および対応方針
- **FISC 安全対策基準への対応経験**: 一次資料（FISC 公開情報および金融庁ガイドライン）を継続的に参照することで補強する。
- **AWS Landing Zone Accelerator (LZA) の直接導入経験**: AWS 公式ドキュメントおよび AWS Blog で最新版を継続的に確認し、キャッチアップを継続している。本案件期間中に LZA 構築フェーズが発生する場合は、AWS Solutions Architect (Business Support 経由) と並走する想定。
- **AWS Direct Connect の物理回線設計**: ネットワーク設計の論理面については経験を有しており、物理面についてはネットワークベンダーとの連携を前提として対応する。
- **Organizations / Control Tower の本番運用**: 商談時にクライアント側の管理レベル (既存設計の踏襲 / 新規構築 / 既存改修) を確認のうえ、運用面 (SCP / Service Catalog / Account Factory) を主担当として進める形を提案する。
