# 参画前確認チェックリスト - 金融機関 AWS クラウド共通基盤案件

契約締結前および参画前に確認しておくことが望ましい事項を整理したチェックリストである。事前に確認することで、参画後の認識齟齬や手戻りを抑制することを目的とする。

---

## A. 案件の前提に関する確認事項

### A-1. スコープおよび体制
- [ ] 共通基盤側のチーム体制（PM／アーキテクト／設計／構築／運用）の現在の人数構成と、本ロールに期待される役割の範囲
- [ ] クラウド移行対象システムの全体像（システム数、業務系／情報系／勘定系の比率、第一波対象システム）
- [ ] 3年間で対象範囲を移行するスケジュールの起点（FY 開始月、プロジェクト開始月）と中間マイルストーン（中間レビュー、経営報告会）
- [ ] 現時点で確定している設計事項（マルチアカウント方式、IaC ツール、CI/CD ツール、監視製品など）と、その決定根拠および議事録の所在
- [ ] 意思決定権を有する関係者の特定（クライアント側 PM、アーキテクト、セキュリティ責任者、監査部門）

### A-2. 契約条件
- [ ] 初回契約期間（3か月／6か月／1年）と更新条件
- [ ] 単価および精算幅（月稼働時間の上限・下限）
- [ ] 本番稼働まで継続する前提か、要件定義／設計フェーズで終了する前提か
- [ ] 増員リソース投入に関する判断プロセスおよび判断権者
- [ ] 契約形態（業務委託／準委任／派遣）

### A-3. 勤務形態
- [ ] 出社頻度の実態と契約上の取り決め（週何日とすることが可能か）
- [ ] 会議体の数および時間帯（朝会、設計レビュー、クライアント定例 等）
- [ ] オフィス所在地、最寄駅、入館手続き
- [ ] 私物 PC 持込可否および貸与 PC の仕様
- [ ] VPN／シンクライアント／リモートデスクトップの方式
- [ ] 利用するコミュニケーションツール（Slack／Teams／Webex 等）

## B. プロジェクト固有の重要確認事項

### B-1. スケジュールの実現可能性
- [ ] 要件定義に充てられる期間と、共通基盤の要件として整理すべき範囲のバランス
- [ ] 要件定義と基本設計を並行実施する方針における、要件未確定状態での設計着手の許容範囲
- [ ] 未確定事項リスト（Issue／課題一覧）の整備状況と件数
- [ ] 各フェーズ間のゲート設定（後工程への持ち込み可否の判断基準）

### B-2. 規制／コンプライアンス
- [ ] FISC 安全対策基準のうち準拠する版（**第13版／2025年3月公表** を基準として確認。先方事情で旧版（第10版／第11版／第12版）準拠が残る場合のみ、例外確認として併用範囲と差分対応方針を整理）
- [ ] 金融庁ガイドライン（サイバーセキュリティ強化方針、システム障害対応に関する指針）の対応必要性
- [ ] 個人情報保護法および個人情報保護委員会ガイドラインの影響範囲
- [ ] データ所在およびリージョン制約（東京リージョン／大阪リージョン／マルチリージョン要件）
- [ ] 海外規制（DORA／FFIEC／OCC 等）の波及可能性（海外拠点経由での参照を含む）
- [ ] 監査対応（外部監査、内部監査、J-SOX）の頻度および形式
- [ ] ログ保管年限（7年／10年など）および保管方式の方針
- [ ] 暗号鍵管理の方針（AWS KMS／AWS CloudHSM／外部 HSM）

### B-3. マルチアカウント方針
- [ ] AWS Landing Zone Accelerator (LZA)、AWS Control Tower、独自構築のいずれを採用するか
- [ ] OU 設計の方針（環境別／事業部別／セキュリティ境界別 など）
- [ ] 共通アカウントの分離（Management／Log Archive／Audit／Network／Shared Services）
- [ ] 既存 Active Directory／Entra ID との連携要件
- [ ] 特権アクセス管理（Break Glass、Just-In-Time Access）の方針

### B-4. ネットワーク
- [ ] オンプレミス接続要件（AWS Direct Connect の本数、帯域、冗長構成）
- [ ] AWS Transit Gateway と AWS Cloud WAN のいずれを採用するか
- [ ] 集中型 Egress（Network Firewall 集約）と分散型のいずれを採用するか
- [ ] 既存ネットワークの保守ベンダー有無および接続点の整理
- [ ] IP アドレス計画および CIDR 体系

### B-5. セキュリティ
- [ ] 導入予定のセキュリティサービス（SecurityHub／GuardDuty／Config／Macie／Inspector／Audit Manager）
- [ ] 委任管理者アカウントの方針
- [ ] AWS WAF および Shield Advanced の要否
- [ ] VPC エンドポイント／PrivateLink の集約方針
- [ ] SIEM 連携要件（Splunk／Datadog／自前 など）

### B-6. IaC／CI/CD
- [ ] 標準とする IaC ツール（Terraform／CDK／CloudFormation）
- [ ] 既存ベンダー納品物との整合方針（既存 CFn 資産がある場合の取扱い）
- [ ] 静的解析ツール（tfsec／Checkov／cfn-nag／cdk-nag）の採用方針
- [ ] パイプライン上の承認ゲート方針（自動承認／手動承認）
- [ ] シークレット管理の方針（Secrets Manager／Parameter Store／HashiCorp Vault など）

### B-7. 監視／運用
- [ ] 監視基盤（CloudWatch のみ、Splunk／Datadog／New Relic との連携）
- [ ] ログ集約方式（S3＋Athena／OpenSearch／Splunk）
- [ ] 障害対応プロセス（オンコール体制、エスカレーションフロー）
- [ ] SLI／SLO の定義（可用性、レイテンシなど）
- [ ] インシデント管理ツール（ServiceNow／Jira Service Management／PagerDuty）

### B-8. 移行戦略
- [ ] 7R（Rehost／Replatform／Repurchase／Refactor／Retire／Retain／Relocate）の比率および優先戦略
- [ ] データ移行方式（AWS DataSync／Database Migration Service／専用回線経由）
- [ ] オンプレミスと AWS の並行運用期間の有無
- [ ] 第一波の対象システム（パイロット移行の対象）

## D. リスクおよび撤退条件

### D-1. 進行上の重大リスク
- [ ] 過去のクラウド案件における延期・中止・撤退の有無
- [ ] 要件未確定のまま設計に入る場合の対処方針
- [ ] 進捗遅延時の追加リソース投入に関する判断権者

### D-2. 担当範囲に関するリスク
- [ ] 専門外領域（AWS Direct Connect 物理設計、既存 AD 連携、業務システム特性など）が業務範囲に含まれるか
- [ ] 「広範な領域に対応可能な人材」として過剰な負荷集中が生じる可能性とその抑止策（契約上のスコープ明確化）
- [ ] 本番稼働まで継続を求められる可能性とその場合の契約条件

### D-3. 撤退条件
- [ ] 契約途中での解除条件（自己都合／先方都合／違約金）
- [ ] 後継者引継ぎ義務の有無

## E. 商談時に開示を依頼することが望ましい資料

商談および面談において、可能な範囲で以下の資料の開示を依頼することが望ましい。

1. 体制図（クライアント側、元請、協力会社）
2. 直近 2 か月程度の要件定義に関する議事録の要旨
3. 要件定義の中間成果物（作成済みのものがあれば）
4. クラウド戦略文書および中期経営計画のクラウド関連箇所
5. 既存のクラウド利用ガイドラインおよびセキュリティ基準
6. FISC および金融庁ガイドラインへの対応方針書

これらの資料が整備されていない場合は、要件定義の進捗状況や論点整理の状況を別途確認する必要がある。

## F. 商談で優先的に確認したい設問（10項目）

1. 共通基盤を利用するシステムの全体数および第一波対象システムは特定されているか。
2. 要件定義の終了時点で未確定として残る論点は、どの程度想定されているか。
3. マルチアカウント方式は AWS Landing Zone Accelerator、AWS Control Tower、独自構築のいずれを採用する方針か。
4. FISC 安全対策基準の準拠版および監査部門の関与時期はどのように整理されているか。
5. 既存ベンダー（メインフレーム、オンプレミスインフラ）との関係性は、協業前提か置換え前提か。
6. 既存 Active Directory／Entra ID との連携方針はどの程度確定しているか。
7. 標準とする IaC ツールおよび既存資産との整合方針はどのように整理されているか。
8. 本ロールの担当範囲は要件定義／設計フェーズに限定されるか、構築・運用フェーズまで継続を想定するか。
9. 出社頻度に関する契約上の取り決めの範囲はどのように設定可能か。
10. 進捗遅延時の追加リソース投入の判断は、どの組織のどの役職が行うか。
