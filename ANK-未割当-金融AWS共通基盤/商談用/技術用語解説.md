# 技術用語解説集 - 金融機関 AWS クラウド共通基盤

## 1. マルチアカウント・ガバナンス

### AWS Organizations
複数の AWS アカウントを一元的に管理するためのサービス。アカウント間の請求統合、Service Control Policy (SCP) によるポリシー適用、Tag Policy などの機能を提供する。

### Organizational Unit (OU)
AWS Organizations 内でアカウントを階層的にグループ化する単位。OU 単位でポリシーや管理を適用できる。代表的な OU 設計として、Security／Infrastructure／Workloads／Sandbox／Suspended／PolicyStaging などがある。

### Service Control Policy (SCP)
AWS Organizations においてメンバーアカウントで実行可能な API を制限するポリシー。Preventive ガードレールとして利用される。

### AWS Control Tower
マルチアカウント環境を自動的に構築・運用するためのマネージドサービス。Landing Zone と呼ばれる初期構成を自動的に展開し、必須ガードレールおよび任意ガードレールを提供する。

### Landing Zone Accelerator on AWS (LZA)
AWS が公開するオープンソースのマルチアカウント基盤構築フレームワーク。Control Tower よりも柔軟な構成が可能で、規制業界（金融、医療、政府等）での採用が想定されている。設定は CloudFormation 経由で展開される。

### Account Factory for Terraform (AFT)
Control Tower の Account Factory を Terraform から制御するための公式ソリューション。GitOps スタイルでアカウントを発行・管理できる。

### Conformance Pack
AWS Config のルールをパッケージ化したテンプレート。複数のルールを一括で適用でき、FISC や CIS、PCI DSS などのフレームワーク対応版が公開されている。

### Delegated Administrator
Organizations 配下のサービス（Security Hub、GuardDuty、Config 等）の管理を、Management アカウント以外のアカウント（通常は Audit アカウント）に委任する仕組み。

### Service Catalog
AWS リソースを利用者向けにテンプレート化して提供できるサービス。承認済みの構成のみを利用者が起動できるようにし、ガバナンスを担保する。

## 2. ネットワーク

### VPC（Virtual Private Cloud）
AWS 上に構築する論理的に分離された仮想ネットワーク。サブネット、ルートテーブル、セキュリティグループ、ネットワーク ACL などで構成される。

### AWS Transit Gateway (TGW)
複数の VPC・VPN・Direct Connect を中央のハブで接続するためのサービス。ハブ＆スポーク型のネットワーク構成を実現する。

### AWS Cloud WAN
複数のリージョン・複数の VPC・オンプレミスを統合的に管理するためのグローバルネットワーク管理サービス。Transit Gateway を内部で活用しつつ、より広域でのネットワーク管理が可能。

### AWS Direct Connect (DX)
オンプレミスと AWS を専用線で接続するサービス。インターネット経由よりも安定した帯域および低レイテンシを実現する。金融機関では冗長構成（2 拠点以上の DX Location 経由）が一般的である。

### Direct Connect Gateway
複数のリージョン・複数のアカウントの VPC を Direct Connect 経由で接続するためのゲートウェイ。

### VPC エンドポイント／PrivateLink
AWS サービスや外部 SaaS への接続をインターネットを経由せず VPC 内から行うための仕組み。Interface 型と Gateway 型がある。

### AWS Network Firewall
VPC レベルでステートフルなファイアウォールを提供するマネージドサービス。集中型 Egress パターンで利用されることが多い。

### AWS WAF
Web アプリケーションへの SQL インジェクション、クロスサイトスクリプティング、Bot などの攻撃を防御するマネージドサービス。Amazon CloudFront、Application Load Balancer、Amazon API Gateway 等と連携する。

### AWS Shield Advanced
DDoS 攻撃に対する高度な保護を提供する有償サービス。金融機関ではミッションクリティカルなシステムで採用される場合がある。

## 3. アイデンティティおよびアクセス管理（IAM）

### AWS Identity and Access Management (IAM)
AWS リソースへのアクセス権限を管理するサービス。IAM ユーザー、IAM ロール、IAM ポリシーを組み合わせて、最小権限の原則に基づいたアクセス制御を行う。

### AWS IAM Identity Center
旧称 AWS SSO。複数の AWS アカウントへのシングルサインオンを提供し、外部 IdP（Microsoft Entra ID、Okta 等）との連携が可能。Permission Set を用いて職務別の権限を割り当てる。

### Permission Set
AWS IAM Identity Center で定義する権限のテンプレート。ジョブ機能（管理者、開発者、読み取り専用 等）別に作成し、ユーザー／グループに割り当てる。

### Break Glass アクセス
緊急時にのみ使用する高権限アカウント。通常は厳重に保管し、利用時には複数人の承認や記録を必須とする運用が一般的。

### Just-In-Time (JIT) アクセス
通常は最小権限で運用し、必要なときだけ一時的に権限を昇格させるアプローチ。AWS では IAM Identity Center や AWS Systems Manager Session Manager と組み合わせて実現する。

### IAM Access Analyzer
リソースポリシーを分析し、外部アカウントからのアクセスを検出するサービス。

## 4. セキュリティサービス

### AWS Security Hub
複数のセキュリティサービス（GuardDuty、Inspector、Macie、Config 等）の検出結果を集約・可視化するサービス。AWS Foundational Security Best Practices、CIS AWS Foundations Benchmark、PCI DSS などの標準に対する準拠状況を評価できる。

### Amazon GuardDuty
機械学習を用いた脅威検出サービス。CloudTrail、VPC Flow Logs、DNS Logs などを分析し、不正アクセスや異常な挙動を検出する。

### AWS Config
AWS リソースの設定変更を記録し、ポリシーに対する準拠状況を評価するサービス。Conformance Pack による一括ルール適用が可能。

### AWS CloudTrail
AWS API コールの監査ログを記録するサービス。組織トレイルにより、Organizations 配下の全アカウントのログを一元管理できる。

### Amazon Macie
S3 バケット内の機密データ（個人情報、クレジットカード番号 等）を機械学習で検出するサービス。

### Amazon Inspector
EC2 インスタンス、コンテナイメージ、Lambda 関数の脆弱性を自動検出するサービス。

### AWS Audit Manager
監査対応に必要な証跡を自動的に収集・整理するサービス。FISC、PCI DSS、HIPAA などの監査基準に対応した事前定義フレームワークが提供されている。

### Amazon Detective
GuardDuty 検出結果や CloudTrail ログをグラフ可視化し、インシデント調査を支援するサービス。

## 5. データ保護および暗号化

### AWS Key Management Service (KMS)
暗号鍵の作成・管理・利用を行うマネージドサービス。AWS マネージドキーとカスタマーマネージドキー (CMK) がある。

### AWS CloudHSM
ハードウェアセキュリティモジュール (HSM) をクラウド上で利用できるサービス。FIPS 140-2 Level 3 認証を取得。FISC などの規制要件で HSM が必須となる場合に採用される。

### External Key Store (XKS)
AWS の外部（オンプレミスやサードパーティ HSM）に保管した鍵を AWS KMS から利用できる機能。

### AWS Secrets Manager
データベース認証情報、API キーなどの機密情報を保管・自動ローテーションするサービス。

### AWS Systems Manager Parameter Store
設定情報や機密情報を階層的に保管するサービス。Secrets Manager よりも軽量。

## 6. IaC（Infrastructure as Code）

### Terraform
HashiCorp が開発する IaC ツール。AWS／Azure／GCP など複数のクラウドに対応する。金融機関での採用率が高い。

### AWS CloudFormation
AWS 公式の IaC サービス。JSON または YAML でリソースを定義する。AWS LZA や AWS Control Tower の内部で利用される。

### AWS Cloud Development Kit (CDK)
TypeScript、Python などのプログラミング言語で AWS リソースを定義できる IaC ツール。内部的に CloudFormation を生成する。

### BLEA (Baseline Environment on AWS)
AWS が公開する CDK ベースのリファレンス実装。金融機関向けの BLEA for FSI（Financial Services Industry）も公開されている。

### 静的解析ツール
- **tfsec**: Terraform コードのセキュリティ設定不備を検出
- **Checkov**: Terraform、CloudFormation、Kubernetes など複数の IaC に対応
- **cfn-nag**: CloudFormation の設定不備を検出
- **cdk-nag**: CDK で生成されるリソースの設定不備を検出

### CloudFormation Hooks
CloudFormation スタックの操作前にカスタムロジックでバリデーションを実行する仕組み。Proactive ガードレールとして利用される。

## 7. CI/CD

### AWS CodePipeline
AWS マネージドの CI/CD オーケストレーションサービス。AWS CodeBuild、AWS CodeDeploy などと連携する。

### AWS CodeBuild
ソースコードのビルド・テストを実行するマネージドサービス。

### AWS CodeArtifact
パッケージレジストリのマネージドサービス（npm、Maven、PyPI、NuGet 等に対応）。

### GitHub Actions
GitHub に統合された CI/CD サービス。OIDC を用いて AWS への認証を行うことが推奨される。

### 承認ゲート
パイプライン上で本番デプロイ前などに人手の承認を要求する仕組み。金融機関では CAB (Change Advisory Board) と連動した運用が一般的である。

## 8. 監視・運用・可観測性

### Amazon CloudWatch
AWS のメトリクス、ログ、アラームを統合的に管理するサービス。

### CloudWatch Logs Insights
CloudWatch Logs に対してクエリベースの検索・分析を実行する機能。

### AWS X-Ray
分散トレーシングサービス。2026 年に X-Ray SDK／Daemon がメンテナンスモードに移行しており、新規実装では AWS Distro for OpenTelemetry (ADOT) の採用が推奨される。

### AWS Distro for OpenTelemetry (ADOT)
OpenTelemetry の AWS 公式ディストリビューション。トレース／メトリクス／ログを統合的に収集する。

### AWS Systems Manager Incident Manager
インシデント発生時の通知、対応、事後レビューを支援するサービス。

### SLI／SLO
- **SLI (Service Level Indicator)**: サービスレベルの計測指標（可用性、レイテンシ等）
- **SLO (Service Level Objective)**: SLI に対する目標値

### Runbook／Playbook
運用作業や障害対応の手順書。AWS Systems Manager Automation により自動化された Runbook も提供できる。

## 9. コスト管理

### AWS Cost Explorer
コストおよび使用量を可視化・分析するサービス。

### Cost and Usage Report (CUR)
詳細なコスト情報を S3 に出力する仕組み。2026 年 4 月以降、CUR 2.0 で IAM Principal 列が追加され、利用者単位での詳細分析が可能となっている。

### AWS Compute Optimizer
EC2、Lambda、EBS、Auto Scaling グループ等の最適化を推奨するサービス。

### Tag Policy
Organizations の機能の一つで、リソースに付与するタグの形式を強制する。コスト配分や統制に利用される。

### Cost Categories
複数のディメンション（アカウント、タグ、サービス等）を組み合わせて、コストを分類・集計するための仕組み。

## 10. 移行戦略

### 7R 戦略
AWS が定義する移行戦略の分類。

- **Retire**: 業務価値がないシステムを廃止する。
- **Retain**: 規制や依存関係の都合で移行せずオンプレミスに残す。
- **Rehost (Lift and Shift)**: 大幅な変更を加えずにそのまま移行する。
- **Relocate**: VMware 環境を VMware Cloud on AWS に移動するなど、構成を変えずに移動する。
- **Repurchase (Drop and Shop)**: SaaS への置換などにより買い替える。
- **Replatform (Lift, Tinker and Shift)**: マネージドサービス利用などの軽微な変更を加えて移行する。
- **Refactor / Re-architect**: アーキテクチャを再設計する。

### AWS Migration Acceleration Program (MAP)
AWS が提供する移行支援プログラム。Assess（評価）／Mobilize（基盤整備）／Migrate & Modernize（実行）の 3 フェーズで構成される。

### AWS Application Migration Service (MGN)
サーバーを最小停止で AWS に移行するためのサービス。

### AWS Database Migration Service (DMS)
データベースを最小停止で移行するためのサービス。

### AWS DataSync
オンプレミスストレージと AWS ストレージ間でデータを効率的に転送するためのサービス。

### AWS Snowball ／ Snowmobile
大容量データを物理デバイスで AWS に転送するためのサービス。

## 11. 金融規制および業界ガイドライン

### FISC 安全対策基準
公益財団法人金融情報システムセンター (FISC) が策定する、金融機関の情報システムにおける安全対策基準。最新版は第 13 版（2025 年 3 月公表）。クラウド利用に関する記述が継続的に拡充されている。

### AWS FISC 対応リファレンス
AWS パートナー各社（NRI、SCSK、ISID 等）が共同で作成した、FISC 安全対策基準と AWS サービスの対応を整理したドキュメント。第 2 版は 2024 年 8 月発行で、FISC 第 11 版対応。第 13 版への対応は順次更新される。

### 金融庁サイバーセキュリティガイドライン
金融庁が策定する金融機関向けのサイバーセキュリティガイドライン。2024 年 10 月公表版が現行版で、175 項目の対応事項を定めている。

### 金融庁オペレーショナル・レジリエンス
金融機関の業務継続能力に関する金融庁の方針。重要な業務の定義、耐性度、4 つの基本動作などを定義する。

### 金融庁 TPCRM 報告書（Third Party Cyber Risk Management）
2026 年 4 月 3 日公表の調査報告書。クラウド事業者を含む第三者リスク管理について、N 次パーティの管理、集中リスク、監査権、出口戦略などを整理している。

### 日本銀行 クラウド管理項目
日本銀行が金融機関のクラウド利用に際して整理した管理項目集。暗号鍵ライフサイクル、特権 ID／JIT、ログ管理、出口戦略などを含む。

### AWS Well-Architected Framework Financial Services Industry Lens
AWS Well-Architected Framework の金融業界向け拡張。レジリエンス、セキュリティ、データプライバシーに関するベストプラクティスを補完する。

### FSI Lens for FISC
FSI Lens を FISC 安全対策基準への対応にマッピングしたバージョン。

### 金融リファレンスアーキテクチャ日本版
AWS が公開する金融機関向けリファレンスアーキテクチャ。BLEA for FSI（ガバナンス基盤）に加え、勘定系・コンタクトセンター・顧客チャネル・マーケットデータ・オープン API（FAPI 含む）・データ分析・モバイル・サイバーレジリエンス・生成 AI の 9 ワークロードに対応した CDK サンプルを提供する。

### ISMAP（Information system Security Management and Assessment Program）
政府情報システムにおけるクラウドサービスの安全性評価制度。金融機関も参照することがある。

### DORA（Digital Operational Resilience Act）
EU のデジタルオペレーショナルレジリエンス法。EU 拠点を持つ金融機関や、EU 規制対象の取引を行う日本の金融機関のグローバル拠点での参照が想定される。

### 経済安全保障推進法（特定社会基盤事業者制度）
重要インフラ事業者に対し、特定重要設備の導入・変更に際して事前届出を求める制度。金融機関は特定社会基盤事業者として指定されている。

### FAPI（Financial-grade API）
OpenID Foundation が策定する、金融機関向けの高セキュリティ API 仕様。オープンバンキング等で参照される。

### J-SOX
日本版企業改革法。財務報告に係る内部統制の評価および監査に関する基準。クラウド基盤の IT 統制も対象範囲。
