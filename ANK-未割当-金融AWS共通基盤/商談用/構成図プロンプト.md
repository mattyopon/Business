# 資料作成用プロンプト（公開版）

## 概要

本ドキュメントは、金融機関向け AWS クラウド共通基盤の提案資料および構成図を作成するためのプロンプト集である。AWS 公式リファレンスアーキテクチャ、AWS Well-Architected Framework Financial Services Industry Lens、AWS 金融リファレンスアーキテクチャ日本版に基づいた構成を前提とする。

実際の案件特有情報（クライアント社名、システム名、IP レンジ等の具体値）は本資料には記載しない。提案資料化の段階で必要に応じて差し替える。

---

## プロンプト1: PowerPoint 提案資料の作成

```
金融機関向け AWS クラウド共通基盤の提案資料を PowerPoint 形式で作成してください。

【プロジェクト概要】
- プロジェクト名: 金融機関向け AWS クラウド共通基盤 要件定義・基本設計
- リージョン: ap-northeast-1（東京）を主、ap-northeast-3（大阪）を DR
- 環境: 本番／ステージング／開発／検証の 4 環境構成（OU 別）
- 設計原則: AWS Well-Architected Framework + FSI Lens for FISC 準拠、FISC 安全対策基準（第 13 版）対応、金融庁サイバーセキュリティガイドライン対応

【スライド構成（10〜15 スライド程度）】

1. エグゼクティブサマリー
   - クラウド共通基盤の目的（ガバナンス／スピード／コスト／規制対応／人材）
   - 全体方針

2. 全体アーキテクチャ
   - AWS Organizations、OU 階層、共通アカウント分離
   - LZA / Control Tower の採用方針

3. マルチアカウント設計
   - OU 構成（Security／Infrastructure／Workloads／Sandbox／PolicyStaging／Suspended）
   - 共通アカウント（Management／Log Archive／Audit／Network／Shared Services）
   - アカウント発行ワークフロー

4. ネットワーク設計
   - Direct Connect 冗長構成
   - Transit Gateway を中心としたハブ＆スポーク
   - 集中型 Egress（AWS Network Firewall）
   - VPC エンドポイント／PrivateLink

5. IAM / アイデンティティ
   - AWS IAM Identity Center
   - Entra ID／オンプレ AD との連携
   - Permission Set 設計
   - Break Glass アクセスおよび JIT アクセス

6. セキュリティサービス委任設計
   - GuardDuty／Security Hub／Config／CloudTrail／Macie／Inspector／Audit Manager
   - Audit アカウントを Delegated Administrator として配置

7. データ保護および暗号化
   - AWS KMS／AWS CloudHSM／External Key Store
   - データ転送時／保存時暗号化

8. IaC / CI/CD
   - Terraform 標準、AWS LZA／Control Tower 部分は CloudFormation 併用
   - 静的解析（tfsec／Checkov／cdk-nag）
   - 承認ゲート設計（CAB 連動）

9. 監視・運用・可観測性
   - CloudWatch を中心、ログ集約は S3＋Athena／OpenSearch
   - AWS Distro for OpenTelemetry (ADOT)
   - インシデント管理（Systems Manager Incident Manager）

10. 規制対応（FISC、金融庁ガイドライン）
    - 管理策と AWS 実装のマッピング表
    - AWS Audit Manager の活用
    - FSI Lens for FISC の WAR 実施

11. ガードレール設計
    - Preventive (SCP)／Detective (Config Rules)／Proactive (CloudFormation Hooks)
    - 例外申請プロセス

12. コスト管理
    - タグ戦略、Cost Categories
    - 配賦モデル

13. 移行戦略（7R）
    - パイロット移行
    - 並走期間設計

14. 導入スケジュール
    - 要件定義／設計／構築／テスト／本番移行のフェーズ別

15. まとめ・次のアクション

【表現のトーン】
- 公式文書調、第三者が読んでも違和感のない中立的な表現
- AWS 公式アイコンを使用
- AWS 公式カラー（オレンジ #FF9900、ダークブルー #232F3E）を基調
- 各スライドに 1 つの図またはダイアグラムを配置
```

## プロンプト2: 全体構成図の作成

```
金融機関向け AWS クラウド共通基盤の全体構成図を作成してください。

【描画範囲】
- AWS Organizations 全体（Root → OU 階層 → アカウント）
- マルチアカウント構成（Management、Log Archive、Audit、Network、Shared Services、Workloads）
- リージョン構成（東京リージョン主、大阪リージョン DR）

【コンポーネント】
- AWS Organizations および OU
- AWS Control Tower / Landing Zone Accelerator (LZA)
- AWS IAM Identity Center（Entra ID／オンプレ AD 連携）
- AWS Transit Gateway（ハブ＆スポーク）
- AWS Direct Connect（冗長構成、2 つの DX Location）
- VPC（Workloads 各アカウント）
- セキュリティサービス委任配置（GuardDuty／Security Hub／Config／CloudTrail／Macie／Inspector／Audit Manager）
- ログ集約（CloudTrail → S3 → Athena / OpenSearch）

【表現のトーン】
- AWS 公式アイコンセット使用
- 配色: AWS オフィシャル（オレンジ／ダークブルー／グレー）
- 矢印は青色で統一、データフローと制御フローを分けて色分け
```

## プロンプト3: セキュリティ多層防御図

```
金融機関向け AWS クラウド共通基盤のセキュリティ多層防御図を作成してください。

【描画範囲】
- 外部からの脅威に対する多層防御
- アカウント間および VPC 間の境界防御

- データ保護（暗号化、鍵管理）

- AWS WAF（CloudFront／ALB の前段）
- AWS Shield Advanced
- AWS Network Firewall（集中型 Egress）
- VPC Security Group / NACL
- AWS PrivateLink / VPC Endpoint
- AWS IAM Identity Center / Permission Set
- AWS KMS / AWS CloudHSM
- Amazon GuardDuty / AWS Security Hub / AWS Config
- AWS CloudTrail（組織トレイル）
- Amazon Macie / Amazon Inspector
- AWS IAM Access Analyzer

【表現のトーン】
- 防御レイヤーを左から右にフロー
- 各レイヤーで防御するリスクを注釈表示
- AWS 公式アイコンセット使用
```

## プロンプト5: 監視・運用ダッシュボード構成

```
金融機関向け AWS クラウド共通基盤の監視・運用ダッシュボード構成図を作成してください。

【描画範囲】
- メトリクス収集、ログ集約、トレース収集の全体像
- 通知・アラート経路
- インシデント管理連携

【コンポーネント】
- Amazon CloudWatch（メトリクス、ログ、アラーム）
- AWS CloudTrail（API 監査）
- AWS Distro for OpenTelemetry (ADOT)（トレース、メトリクス、ログ）
- ログ集約: CloudWatch Logs → S3（長期保管） / OpenSearch（検索） / Athena（クエリ）
- Amazon SNS / Amazon EventBridge
- AWS Systems Manager Incident Manager
- 外部 SaaS 連携: PagerDuty / Opsgenie（オプション）
- 監査ログの長期保管: S3 Glacier Deep Archive、Object Lock

【表現のトーン】
- データフローを矢印で明示
- 短期保管（30 日）／中期保管（1〜3 年）／長期保管（7〜10 年）をレイヤー分け
- AWS 公式アイコンセット使用
```
