# 07. FISC・金融規制 対応マッピング指針

本書は、金融機関向け AWS クラウド共通基盤において、対応すべき主要な金融規制および業界ガイドラインと、AWS サービスへのマッピング指針をまとめたものである。

実際の案件では、対象金融機関の業態（銀行／損保／生保／証券／カード／資金移動／暗号資産 等）および取扱業務に応じて適用範囲を絞り込むこと。

## 2. FISC 安全対策基準 第 13 版の主な改訂ポイント

第 11 版から第 13 版への改訂で、特に共通基盤要件定義に影響する論点は以下のとおり。

1. **経済安全保障対応**: 特定社会基盤事業者に指定された金融機関等に求められる対応の取り込み
2. **オペレーショナル・レジリエンス**: 金融庁 2023-04 公表 DP に基づく耐性度（Tolerance for Disruption）の参考情報追加
3. **サイバーガイドライン整合**: 金融庁 2024-10-04 ガイドラインを踏まえた基準小項目の新設・見直し
4. **AI 安全対策新設**: AI・生成 AI に関する安全対策の基準小項目新設
5. **改訂規模**: 全体の約 3 割が変更（複数の二次資料に基づく見立て）

要件定義時には、AWS パートナーが提供する FISC 対応リファレンスが第 13 版に更新されているかを確認する必要がある。

## 3. 金融庁サイバーセキュリティガイドライン（2024-10-04）の主要対応事項

### 3-1. クラウドサービス利用時の対策（2.3.4.5 節）

公表文の趣旨：

1. 利用するクラウドサービスの仕様を確認し、理解を深める
2. 責任共有モデルを理解し、クラウド事業者との責任範囲を明確化
3. 設定不備の自動検知・診断サービスの活用
4. サービス仕様変更時の影響確認
5. 関係主体の把握とインシデント対応体制の構築
6. 利用終了時のデータの論理的廃棄

### 3-2. サードパーティリスク管理（2.6 節）

公表文の趣旨：

- サードパーティの特定とリスク評価
- 管理台帳の整備
- デューデリジェンスの実施

### 3-3. データ保護・暗号化（2.3.3 節）

公表文の趣旨：

- データ管理方針の策定
- 暗号化方式、暗号鍵・電子証明書のライフサイクル管理
- 危殆化時の対応
- CRYPTREC 暗号リストの参照

### 3-4. 認証・特権 ID 管理

公表文の趣旨：

- 特権アカウントの厳格な制限・管理（多要素認証必須）
- リモートアクセスでの多要素認証必須
- 外部委託先のアクセス権管理

### 3-5. TLPT（脅威ベースのペネトレーションテスト）

公表文の趣旨：

- 定期的な TLPT の実施
- 金融庁「TLPT 実施にあたっての手引書」の参照

## 4. 規制要件と AWS サービスの対応マッピング（抜粋）

実際の案件では、規制要件と AWS サービスのマッピング表を詳細化する。代表的なマッピング例を以下に示す。

| 規制領域 | 要求事項 | 対応 AWS サービス例 | 共通基盤での実装方針例 |
|---------|---------|---------------------|------------------------|
| クラウド設定不備の自動検知 | 設定の妥当性確認 | AWS Config、Security Hub、IAM Access Analyzer | 全アカウントで強制有効化、Conformance Pack 適用 |
| 特権 ID 管理 | 多要素認証、利用制限 | AWS IAM Identity Center、IAM、MFA、Session Manager | Permission Set 設計、Break Glass、JIT アクセス |
| 暗号化 | データ管理方針、ライフサイクル | AWS KMS、AWS CloudHSM、External Key Store | CMK 標準、鍵ローテーション、鍵分離 |
| 監査ログ | 改ざん防止、長期保管 | AWS CloudTrail（組織トレイル）、Amazon S3 Object Lock、S3 Glacier | Log Archive アカウントに集約、Object Lock、Glacier 長期保管 |
| 脅威検出 | 不正アクセス検知 | Amazon GuardDuty、Amazon Inspector、Amazon Macie | Audit アカウントに委任、全アカウント有効化 |
| サードパーティ管理 | 台帳整備、リスク評価 | AWS Audit Manager、共通基盤運用ドキュメント | 共通基盤側で雛形提供、利用システム側で個別記載 |
| データの論理的廃棄 | 利用終了時のデータ削除 | S3 オブジェクト削除＋KMS 鍵削除＋バージョニング履歴削除 | 廃棄手順書を整備、削除証跡の保管 |
| TLPT | 脅威ベースのペネトレーションテスト | AWS のサポートを得たレッドチーム演習 | 共通基盤対象の TLPT 実施計画 |
| データ越境移転 | 提供先国情報の確認 | リージョン制約、Region Deny SCP | 東京リージョン制約、例外のみ承認 |
| 経済安全保障 | 特定重要設備の事前届出 | ISMAP 登録クラウドの選定 | クラウド選定基準への組込み |
| 出口戦略 | サービス利用終了時の移行 | データエクスポート、IaC による再構築可能性 | 出口戦略ドキュメントの整備 |

## 6. 要件定義時の重要確認事項

1. FISC 安全対策基準の準拠版（第 13 版を前提とするか、第 11 版で開始するか）
2. AWS パートナーが提供する FISC 対応リファレンスのバージョン（第 13 版対応版が出ているか）
3. 経済安全保障推進法の特定社会基盤事業者指定の有無と対応方針
4. 金融庁サイバーセキュリティガイドライン 175 項目のトレーサビリティマトリクスの整備
5. オペレーショナル・レジリエンス（耐性度）の AWS 障害シナリオへの反映
6. 越境移転規制（個情法 28 条）への対応（リージョン制約、サポート要員の所在）
7. ISMAP 登録クラウドの選定基準
8. DORA の影響範囲（EU 拠点を持つ場合）
9. 出口戦略（exit plan）の文書化
10. TLPT 実施計画の整備
